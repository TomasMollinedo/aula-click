# Decisiones — Aula Click

Registro corto de decisiones de arquitectura. Una decisión **tomada** no se cambia sin acuerdo del equipo; si cambia, se actualiza acá y en el doc afectado en el mismo PR. Lo que depende de una decisión **abierta** no se implementa suponiendo una respuesta (`AGENTS.md`, regla 7).

| T-04 | Prisma 7 con `@prisma/adapter-pg`                                                                                                                                                                                                                                                                                                                                           | Driver `pg` en lugar del engine binario clásico                                                                                                                                                   |
| T-05 | Backend feature-first en capas (routes, controller, validation, service, repository); entre features solo se importan repositories                                                                                                                                                                                                                                          | Sin ciclos entre features y sin acoplar reglas de negocio                                                                                                                                         |
| T-06 | Frontend feature-first en `src/features/<entidad>/`; `components/` solo para UI sin entidad                                                                                                                                                                                                                                                                                 | Todo lo de una entidad junto. | T-07 | En el frontend, los datos se piden desde Client Components con TanStack Query + `fetchJson`; ningún Server Component hace `fetch` a `/api/v1`                                                                                                                                                                                                                               | En el servidor una URL relativa no funciona y la cookie no viaja; un solo camino de datos y un solo manejo de errores                                                                             |
| T-08 | Los schemas de Zod no se comparten entre front y back                                                                                                                                                                                                                                                                                                                       | El frontend no puede importar `src/server` (ESLint). Cada lado valida lo suyo; la validación que manda es la de la API                                                                            |
| T-09 | Sin `axios` ni `react-router`                                                                                                                                                                                                                                                                                                                                               | Ver `dependencias.md` → Lo que no se instaló                                                                                                                                                      |
| T-10 | Fechas de calendario como `@db.Date` / `YYYY-MM-DD`; horas como minutos / `HH:mm`; zona `America/Argentina/Salta`                                                                                                                                                                                                                                                           | Comparaciones simples y sin errores de zona horaria                                                                                                                                               |
| T-11 | Paginación por offset con respuesta `{ data, meta }`                                                                                                                                                                                                                                                                                                                        | Simple, suficiente para el volumen del centro                                                                                                                                                     |
| T-12 | Búsqueda sin tildes con columna `busqueda` normalizada; sin `unaccent`                                                                                                                                                                                                                                                                                                      | `mode: 'insensitive'` no resuelve tildes y así no depende de extensiones de Postgres                                                                                                              |
| T-13 | Archivos: se guarda la clave; la subida va por multipart a la API; la lectura, con URL prefirmada (900 s)                                                                                                                                                                                                                                                                   | Un solo punto que conoce MinIO y URLs que no quedan viejas en la base                                                                                                                             |
| T-14 | `proxy.ts` protege todo por defecto (matcher negativo)                                                                                                                                                                                                                                                                                                                      | Una sección nueva queda protegida sin acordarse de tocar el proxy                                                                                                                                 |
| T-15 | Header y Sidebar se montan con `AppShell` en el layout de cada segmento de rol; el layout raíz no lleva Header                                                                                                                                                                                                                                                              | `/login` queda sin el esqueleto de la app autenticada                                                                                                                                             |
| T-16 | Documentación: `AGENTS.md` transversal + `docs/` por tema + `.claude/rules/` por zona                                                                                                                                                                                                                                                                                       | Contexto chico para las herramientas de IA y una sola fuente por tema                                                                                                                             |
| T-17 | Valores de `role`: `MESA_ENTRADAS`, `PROFESOR`, `GERENTE`, `ALUMNO`. Un usuario tiene un solo rol (antes D-01)                                                                                                                                                                                                                                                              | Siguen la convención de enums del dominio (`ACTIVO`, `RECURRENTE`): español, mayúsculas y guion bajo                                                                                              |
| T-18 | Los alumnos tienen usuario y portal, en el Sprint 3 (antes D-02)                                                                                                                                                                                                                                                                                                            | Decisión del equipo                                                                                                                                                                               |
| T-19 | Cada rol tiene un segmento real de URL: `/mesa`, `/profesor`, `/gerente`, `/portal`. No se usan route groups para separar roles (antes D-06)                                                                                                                                                                                                                                | Las URLs de distintos roles no pueden chocar y el rol queda visible en la ruta                                                                                                                    |
| T-20 | Turnos recurrentes: se guarda la regla (`fechaInicio` y `fechaFin` opcional) y las fechas que no aplican en `TurnoExcepcion`; las ocurrencias se expanden al consultar. La prioridad no se persiste. En una `SESION_UNICA`, `fechaFin = fechaInicio`. El estado del turno es `ACTIVO` / `CANCELADO` y la vigencia se calcula por fechas, nunca por el estado (antes D-03)   | Una fila por turno en lugar de una por ocurrencia; "vigente" es una sola condición sobre `fechaFin`; la prioridad depende de la fecha de examen, que puede cambiar                                |
| T-21 | Las cuentas se crean escribiendo `Usuario` + `Account` (`providerId: 'credential'`, `accountId` = id del usuario) con la contraseña hasheada por `hashPassword()` de `src/lib/auth.ts`. Así lo hace el seed, que crea el primer gerente. No se usa `auth.api.signUpEmail` ni el plugin `admin` (antes D-05)                                                                 | `signUpEmail` queda bloqueado con `disableSignUp`; el plugin `admin` trae su propio campo `role`. Un solo mecanismo para el seed y el alta de profesor, con el mismo hasher que verifica el login |
| T-22 | `Profesor` tiene un FK único y obligatorio a `Usuario` (`usuarioId`). Mesa de entradas crea la cuenta del profesor con una contraseña inicial (mecanismo de T-21). Los datos personales, la búsqueda y la baja lógica del profesor son los de su `Usuario` (`Usuario.estado`) (antes D-10)                                                                                  | Un profesor siempre puede iniciar sesión y no se duplican datos personales entre `Usuario` y `Profesor`. El vínculo del alumno con su usuario llega con el portal (Sprint 3)                      |
| T-23 | Modelo de datos: `Rol` es un catálogo con PK de texto (los valores de T-17) y `Usuario.role` es un FK a él; `Usuario.id` es `String` (lo genera Better Auth) y el resto de las entidades usa `Int` autoincremental; `Session`, `Account` y `Verification` conservan los nombres de Better Auth y el usuario es el modelo de dominio `Usuario` (`user.modelName: 'usuario'`) | Better Auth recibe el rol como string y la base impide valores inválidos; las tablas de Better Auth son infraestructura y no se renombran campo por campo                                         |
| T-24 | La sesión vence tras 60 minutos sin uso y se renueva con la actividad (`SESION_INACTIVIDAD_SEGUNDOS` en `src/lib/auth-reglas.ts`); `rememberMe` no cambia la duración (antes D-11)                                                                                                                                                                                          | Confirmado por los PO. Un solo vencimiento, por inactividad, para todos los roles                                                                                                                 |
| T-25 | Alta de alumno con datos mínimos: nombre, apellido, DNI, fecha de nacimiento, email y teléfono; datos del tutor (nombre, apellido, teléfono y email) obligatorios si es menor. El resto es opcional                                                                                                                                                                         | Confirmado por las PO (el teléfono también, a pedido de ellas)                                                                                                                                    |
| T-26 | Primitivos de UI: shadcn/ui sobre Radix, con el código copiado a `components/ui/` (no queda como dependencia opaca) (antes D-08)                                                                                                                                                                                                                                            | Resuelve gratis la accesibilidad de teclado/foco de `Dialog` y `Select`, que las pantallas ya necesitan (modal de detalle del alumno, selector de materias); el código sigue siendo tan editable como si fuera hecho a mano |
| T-27 | Alta, detalle y edición de una entidad se abren como modal sobre el listado (Parallel + Intercepting Routes, slot `@modal`) y como página al entrar por URL, con las mismas URLs                                                                                                                                                                                            | El diseño de las PO los muestra como modal; las URLs siguen siendo compartibles y enlazables desde otras features, y Atrás cierra el modal                                                        |
| T-28 | El formulario de alumno anticipa si es menor de edad (`features/alumnos/edad.ts`, misma cuenta que el backend) solo como ayuda visual: muestra el aviso y los asteriscos del tutor, pero no bloquea el envío. La validación es de la API y sus 400 se muestran en los campos                                                                                                | El diseño muestra el aviso mientras se tipea la fecha; la regla tiene una sola fuente (la API)                                                                                                    |
